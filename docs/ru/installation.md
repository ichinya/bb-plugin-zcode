# Установка

Для работы нужны BB 0.49+, ZCode Desktop с выполненным входом и Rust-бинарник `zcode-acp`. Встроенный runtime ZCode выбирается автоматически; отдельная установка Node.js необязательна. В Windows также нужен Windows PowerShell 5.1 для прав на сессии. Для сборки плагина из исходников по инструкции ниже используются Node.js 24+/npm; для сборки бинарника нужен Rust.

## 1. Установите плагин

Установите плагин ZCode и откройте **Настройки → ZCode CLI**. В блоке **zcode-acp · Rust** выберите компьютер, на котором будет работать агент. Панель показывает используемую версию, последний стабильный релиз и путь к бинарнику.

Нажмите **Установить**, чтобы скачать бинарник для этого компьютера. Для обновления: **Проверить обновления → Обновить**. Плагин проверяет SHA-256 и ответ Rust-бинарника с его версией перед переключением. Поддерживаются Windows x64, Linux x64 и macOS Intel/Apple Silicon. Файлы сохраняются в постоянную папку данных плагина; установленное приложение ZCode не изменяется.

Оставьте **Исполняемый файл ACP** пустым, чтобы автоматически использовать скачанную версию. Указанный вручную путь сохраняет приоритет. После скачивания кнопка **Использовать установленный ACP** очистит этот параметр для всех компьютеров. Работающие чаты сохраняют старый бинарник до следующего запуска ACP; обновление не заменяет исполняемый файл, который удерживает Windows.

Если релиз только опубликован, дождитесь завершения сборки бинарников и повторите проверку. Если релизов ещё нет, панель сообщает об этом и отключает установку. Ошибка загрузки или проверки сохраняет предыдущую установленную версию.

## Необязательно: установите ACP самостоятельно

Соберите из отдельного репозитория:

```sh
git clone https://github.com/ichinya/zcode-acp.git
cd zcode-acp
cargo install --path . --locked
zcode-acp --version
cd ..
```

Папка bin Cargo должна быть в PATH, доступном BB. После изменения PATH перезапустите BB. Другой вариант — хранить release-бинарник в любой папке и указать полный путь в параметре **Исполняемый файл ACP**. Подробности — в разделе [самостоятельного запуска](./runtime.md).

## Сборка плагина из исходников

```sh
git clone https://github.com/ichinya/bb-plugin-zcode.git
cd bb-plugin-zcode
npm ci
npm run build
bb plugin install . --yes
```

Плагин сам регистрирует **ZCode CLI** с ID `acp-zcode-cli` и напрямую запускает Rust-бинарник. Зависимости от npm-пакета адаптера и промежуточного JS-лаунчера нет.

Если вы используете собственный бинарник вне PATH, задайте **Исполняемый файл ACP**, например `D:\Tools\zcode-acp.exe`. Иначе оставьте поле пустым: сначала используется установленный плагином бинарник, затем PATH. **Путь к CLI ZCode** — отдельный параметр для установленного `resources/glm/zcode.cjs`; обычно его оставляют пустым. Оба пути относятся к машине, на которой запускается агент.

## 3. Проверьте и выберите модель

```sh
zcode-acp --doctor
```

Если бинарник вне PATH, используйте полный путь. Doctor обращается к сервису аккаунта, не отправляя запрос модели. В новом чате BB выберите **ZCode CLI**, затем модель Coding Plan, Start Plan или личного API-подключения. Подробнее — в [настройке](./configuration.md).

## Обновление

Для бинарника, скачанного плагином, используйте **Проверить обновления → Обновить** в настройках плагина. Сам плагин обновляется отдельно. Если бинарник установлен вручную, обновляйте или собирайте его самостоятельно. Затем:

В Windows открытый чат может удерживать старый исполняемый файл. Соберите новую версию в отдельную папку, например `cargo build --release --locked --target-dir target/versions/0.3.1`, и выберите её `release/zcode-acp.exe` в параметре **Исполняемый файл ACP**. Так обновление не требует замены бинарника работающей сессии.

```sh
git pull --ff-only
npm ci
npm run build
bb plugin reload zcode-acp
```

Провайдер использует текущие настройки плагина для запуска и получения моделей. После смены параметра **Исполняемый файл ACP** перезапустите работающие сессии и обновите модели/квоты. При установке из локальной папки исходники должны оставаться доступны BB.

### Переход с пользовательского ACP-агента

Перед загрузкой этой версии удалите только старую запись ZCode из Custom agents:

```sh
node scripts/register-cli-agent.mjs --register
bb plugin reload zcode-acp
```

Скрипт сохраняет остальных пользовательских агентов. Новый агент он не добавляет: теперь тот же ID регистрирует плагин. При новой установке скрипт не нужен.

Открытые до обновления чаты могут сохранять runtime со старой JS-командой даже после перезагрузки плагина. Для сбойного чата выполните:

```sh
bb thread stop <thread-id>
```

Команда освобождает runtime, сохраняя историю и рабочую папку. Затем нажмите **Retry** в этом чате. Следующий запуск использует текущий Rust-бинарник. `thread clear` для такой миграции не требуется.
