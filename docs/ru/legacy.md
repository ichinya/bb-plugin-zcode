# Прежний мост для macOS

Исходный провайдер **ZCode** (`zcode`) управляет окном Desktop через Accessibility macOS и читает результаты из локальной базы. **ZCode CLI** (`acp-zcode-cli`) использует отдельный нативный ACP-runtime. Для текущей установки выбирайте CLI.

## Требования и установка

GUI-мосту нужны macOS, ZCode Desktop с выполненным входом, Python 3, Node.js и Xcode Command Line Tools с `swiftc`. Из папки этого репозитория:

```sh
scripts/install.sh --default-mode full
```

Скрипт собирает `zcax`, устанавливает `zcbridge` и прежний launcher `zcode-acp` в пользовательскую папку моста и устанавливает плагин BB. Предварительно посмотрите действия через `scripts/install.sh --dry-run`. Для нового нативного провайдера используйте [основную инструкцию](./installation.md).

Разрешите Accessibility в macOS терминалу или процессу Node, который запускает `zcax`. ZCode должен оставаться открытым с выполненным входом. UI-помощник Windows поддерживает только чтение, а не этот способ управления задачами.

В форме доступны режим по умолчанию, приоритет разрешений BB, область автоматических разовых подтверждений, переопределение модели, маршрут оплаты, число параллельных задач, автоматические проекты и передача инструкций. Они относятся к исходной GUI-реализации.

`zcbridge doctor` проверяет мост. `zcbridge --help` перечисляет команды задач, проектов, моделей, квот и разрешений. `zcbridge rewards --claim` явно запрашивает ежедневный бонус; это не шаг установки или проверки нативного ACP-провайдера.

## Ограничения

GUI-управлению нужен разблокированный Mac без сна; оно зависит от интерфейса ZCode. Обновления приложения могут нарушить работу. Очередь задач, управление проектами Desktop и маршрутизация планов отделены от сессий нативного адаптера. Подробный справочник исходного моста находится в [upstream-репозитории](https://github.com/VKirill/bb-plugin-zcode).
