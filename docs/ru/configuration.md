# Настройка

## Выберите ZCode CLI

В новом чате BB откройте выбор модели и выберите **ZCode CLI**. ID провайдера — `acp-zcode-cli`.

![Модели ZCode CLI с названиями источников в каждой строке](/screenshots/model-picker.png)

## Сначала источник, затем модель

| Источник | Авторизация и маршрут |
| --- | --- |
| Coding Plan · Z.ai / BigModel | Использует семейство активного аккаунта Desktop и временные токены проекта. |
| Start Plan · Z.ai / BigModel | Использует вход Desktop и подтверждённый положительный баланс модели с действующим сроком. При недоступности не переключается на Coding Plan. |
| Личное API-подключение, например B.AI | Использует подключение, уже настроенное в ZCode. У каждого источника своя идентичность. |

В BB 0.49 список моделей плоский, поэтому источник указан в названии каждой строки. Coding Plan и Start Plan расположены первыми. Доступность определяется каталогом и сервисом аккаунта; пример на скриншоте не гарантирует тот же набор моделей для другого аккаунта.

Уровни reasoning, например **Low**, **High** и **Max**, берутся из возможностей выбранной модели. Изменение reasoning сохраняет ID модели.

## Разрешения и режимы

| Выбор | Режим ZCode |
| --- | --- |
| Самостоятельный запуск по умолчанию | `build`: спрашивать перед изменениями. |
| BB Accept edits | `edit`. Переменная окружения не может повысить его до `yolo`. |
| BB Full | `yolo`. |
| Явное планирование | `plan`, выбранный через настройки адаптера. |

В запросах разрешений ACP доступны **разрешить один раз** и **отклонить**. Постоянные разрешения не передаются.

## Страница плагина

Блок **zcode-acp · Rust** показывает текущую и последнюю версии для выбранного компьютера. Кнопки **Установить**, **Проверить обновления** и **Обновить** загружают бинарник стабильного GitHub Release с проверкой SHA-256. Подробнее — в [установке](./installation.md).

**Исполняемый файл ACP** (`acpCommand`): пусто — установленный плагином ACP на этом компьютере, затем команда `zcode-acp` из PATH; либо полный путь к Rust-бинарнику, например `D:\Tools\zcode-acp.exe`. Используется для чата, каталога моделей и квот. Ошибочный явный путь не заменяется автоматическим поиском. Аргументы и кавычки оболочки в поле не нужны. После скачивания кнопка **Использовать установленный ACP** очищает указанный вручную путь; параметр действует для всех компьютеров.

**Путь к CLI ZCode**
(`nativeEntry`). Укажите полный путь к `resources/glm/zcode.cjs` на машине агента,
например `D:\Apps\ZCode\resources\glm\zcode.cjs`. Нужен путь к файлу, без
кавычек оболочки. Пустое поле сохраняет автоматический поиск.

Плагин передаёт его **ZCode CLI** через `ZCODE_NATIVE_ENTRY`, включая получение
каталога моделей. Поиск установки и сбор квот используют тот же путь.
Значение читается при каждой новой команде; повторная регистрация не нужна.
После смены установки перезапустите уже работающую ACP-сессию и обновите
список моделей и панель квот.

Модель, план, reasoning и разрешения по-прежнему выбираются в чате.
Квоты Coding Plan и Start Plan находятся в **Provider usage**.

## Вход в аккаунт

Выполните вход в ZCode Desktop. Адаптер читает сохранённую авторизацию и обновляет временные токены проекта в памяти. После обычного перезапуска повторный вход через браузер не нужен. Если сохранённая авторизация истекла или отклонена, переподключите аккаунт в Desktop.

Не используйте `zcode login` как шаг установки. Не копируйте токены в настройки плагина и не добавляйте файлы аккаунта в Git.

## Дополнительные переменные окружения

Остальные дополнительные параметры задаются в **окружении машины агента**. На странице плагина доступны путь к ACP-бинарнику и путь к установке ZCode. Доступные аргументы CLI:

```sh
zcode-acp --help
```

| Переменная | Назначение |
| --- | --- |
| `ZCODE_NODE` | Явное переопределение runtime. По умолчанию выбирается runtime той же установки ZCode, затем Node.js 24+ из PATH. Аргумент `--node` имеет приоритет. |
| `ZCODE_NATIVE_ENTRY` | Абсолютный путь к установленному `resources/glm/zcode.cjs`, если автоматический поиск не сработал. |
| `ZCODE_STORAGE_DIR` | Явная папка данных Desktop; иначе используется `.zcode` внутри базовой/домашней папки. |
| `ZCODE_DATA_BASE_DIR` | Базовая папка для стандартного расположения `.zcode`. |
| `ZCODE_ACP_STATE_DIR` | Папка сессий адаптера; по умолчанию `~/.zcode-bridge/native-acp`. |
| `ZCODE_NATIVE_MODE` | `build`, `plan`, `edit` или `yolo` в пределах разрешений BB. |
| `ZCODE_NATIVE_MEMORY` | `1` включает native memory для будущих сессий. По умолчанию выключено, чтобы избежать фоновых запросов к модели. |

После смены окружения перезапустите работающие ACP-сессии. В Windows папки сессий защищены ACL текущего пользователя, на POSIX используется режим 0700. Сессии ACP имеют ID `bb-native-*` и не подхватывают задачи Desktop.
